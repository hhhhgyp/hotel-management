## BUG-01 房型价格允许为 0

| 字段 | 内容 |
|------|------|
| **缺陷编号** | BUG-01 |
| **严重程度** | 严重（P1） |
| **优先级** | 高 |
| **所属模块** | 房型管理 |
| **关联用例** | TC-011（`test_room_types.py::test_room_type_price_boundary[0-...]`） |
| **缺陷类型** | 逻辑错误 / 边界遗漏 |

**复现步骤**
1. 登录系统，进入「房型管理」→「添加房型」。
2. 名称填「测试房型」，价格填 `0`，可住人数填 `2`。
3. 点击「保存」。

**预期结果**：提示「价格必须大于 0」，不允许保存。

**实际结果**：保存成功，列表出现价格为 0 的房型。

**根因分析**：价格校验条件写成了 `price < 0`，遗漏了 `price == 0` 的边界。正确应为 `price <= 0`。

**建议修复**：把 `if price < 0` 改为 `if price <= 0`。

**状态**：待修复（`app/app.py` 中 `_validate_room_type` 函数）

## BUG-02 预订允许「当天退房」（入住日期 = 退房日期）

| 字段 | 内容 |
|------|------|
| **缺陷编号** | BUG-02 |
| **严重程度** | 严重（P1） |
| **优先级** | 高 |
| **所属模块** | 预订管理 |
| **关联用例** | TC-035（`test_bookings.py::test_booking_same_day_checkout`） |
| **缺陷类型** | 逻辑错误 / 边界遗漏 |

**复现步骤**
1. 进入「预订管理」→「新增预订」。
2. 入住日期和退房日期都填同一天（如 `2026-09-20`）。
3. 其余字段填合法值，点击「提交预订」。

**预期结果**：提示「退房日期必须晚于入住日期」（至少住一晚）。

**实际结果**：预订成功，出现「当天入住当天退房」的订单。

**根因分析**：日期校验条件写成了 `checkout < checkin`，遗漏了 `checkout == checkin` 的边界。正确应为 `checkout <= checkin`。

**建议修复**：把 `if checkout < checkin` 改为 `if checkout <= checkin`。

**状态**：待修复（`app/app.py` 中 `_validate_booking` 函数）

## BUG-03 手机号校验漏检「以 1 开头」

| 字段 | 内容 |
|------|------|
| **缺陷编号** | BUG-03 |
| **严重程度** | 一般（P2） |
| **优先级** | 中 |
| **所属模块** | 预订管理 |
| **关联用例** | TC-030（`test_bookings.py::test_booking_phone[01111111111-...]`） |
| **缺陷类型** | 校验不完整 |

**复现步骤**
1. 进入「新增预订」，手机号填 `01111111111`（0 开头）。
2. 其余字段填合法值，点击「提交预订」。

**预期结果**：提示「手机号格式不正确」。

**实际结果**：预订成功。

**根因分析**：手机号只校验了「11 位数字」，漏了「以 1 开头」。正确应使用正则 `^1\d{10}$`。

**建议修复**：改用 `re.match(r"^1\d{10}$", phone)` 校验。

**状态**：待修复（`app/app.py` 中 `_validate_booking` 函数）

## BUG-04 身份证号只校验长度，不校验格式

| 字段 | 内容 |
|------|------|
| **缺陷编号** | BUG-04 |
| **严重程度** | 一般（P2） |
| **优先级** | 中 |
| **所属模块** | 预订管理 |
| **关联用例** | TC-034（`test_bookings.py::test_booking_id_card[ABCDEFGHIJKLMNOPQR-...]`） |
| **缺陷类型** | 校验不完整 |

**复现步骤**
1. 进入「新增预订」，身份证号填 `ABCDEFGHIJKLMNOPQR`（18 位全字母）。
2. 其余字段填合法值，点击「提交预订」。

**预期结果**：提示「身份证号格式不正确」。

**实际结果**：预订成功。

**根因分析**：身份证只校验了「长度 18」，未校验「前 17 位数字 + 末位数字或 X」。正确应使用正则 `^\d{17}[\dXx]$`。

**建议修复**：改用 `re.match(r"^\d{17}[\dXx]$", id_card)` 校验。

**状态**：待修复（`app/app.py` 中 `_validate_booking` 函数）

## BUG-05 按「维修中」筛选房间时结果错误

| 字段 | 内容 |
|------|------|
| **缺陷编号** | BUG-05 |
| **严重程度** | 一般（P2） |
| **优先级** | 中 |
| **所属模块** | 房间管理（筛选） |
| **关联用例** | TC-042（`test_search_filter.py::test_filter_status_repair`） |
| **缺陷类型** | 逻辑错误 / 分支遗漏 |

**复现步骤**
1. 进入「房间管理」。
2. 状态下拉选择「维修中」，点击「查询」。

**预期结果**：只显示状态为「维修中」的房间（即 302 一间）。

**实际结果**：显示了全部 6 间房（筛选未生效）。

**根因分析**：状态筛选的代码只判断了 `("空闲", "已预订", "已入住")`，漏掉了「维修中」这个状态分支。正确应判断 `VALID_ROOM_STATUS`（包含全部 4 种状态）。

**建议修复**：把 `if status in ("空闲", "已预订", "已入住")` 改为 `if status in VALID_ROOM_STATUS`。

**状态**：待修复（`app/app.py` 中 `rooms` 函数）
