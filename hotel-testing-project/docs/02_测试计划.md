# 测试计划

> 文档作用：在动手写用例之前，先明确「测什么、怎么测、何时算通过」。这是测试的第二步。

## 一、测试目标

1. 验证酒店管理系统的功能与校验规则是否符合需求（见 `01_需求说明.md`）。
2. 尽可能发现系统缺陷，形成缺陷报告。
3. 通过自动化测试脚本沉淀回归能力，保证后续改动不破坏已有功能。

## 二、测试范围

**范围内（In Scope）**
- 登录 / 鉴权
- 房型管理（新增、列表、删除、价格/人数校验）
- 房间管理（新增、编辑、房号唯一、楼层校验）
- 预订管理（新增、退房、格式/日期/冲突校验、状态流转）
- 搜索与筛选

**范围外（Out of Scope）**
- 接口（API）测试
- 性能测试、压力测试
- 安全专项测试（越权、注入等）
- 数据库层面的测试

## 三、测试方法

| 方法 | 应用场景 |
|------|---------|
| 黑盒测试 | 不关注内部实现，只看输入输出是否符合预期 |
| 等价类划分 | 登录、手机号、身份证等输入分有效/无效类 |
| 边界值分析 | 价格、可住人数、楼层、日期等有明确范围的字段 |
| 场景测试 | 预订→退房的状态流转 |
| 自动化测试 | 全部用例用 pytest + Playwright 自动化执行 |

## 四、测试环境

| 项 | 说明 |
|----|------|
| 操作系统 | Windows 11 |
| 浏览器 | Chromium（Playwright 自动管理） |
| 被测应用 | Flask（Python），运行于 http://127.0.0.1:5000 |
| 测试框架 | pytest + pytest-playwright |
| 报告 | pytest-html |

## 六、通过 / 退出标准

**通过标准（验收）**
- 全部用例执行完毕，失败用例均有明确的缺陷记录。
- 无「严重（P1）」级别的未解决缺陷（或已确认可延期）。

**退出标准**
- 已执行完所有计划内的用例并输出测试报告。

## 七、风险与应对

| 风险 | 应对 |
|------|------|
| 测试数据互相污染 | 每个用例前重置数据（fixture 实现隔离） |
| 环境依赖（浏览器下载） | 提前执行 `playwright install chromium` |
| 5000 端口被占用 | 关闭手动启动的应用，或改端口 |
